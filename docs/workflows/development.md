# Development Workflow

Choose the canonical repository before creating a branch. Use a branch named with the Linear issue ID, make the smallest scoped change, update repository-specific documentation in the same PR when needed, and let the repository CI define the technical gates.

If a task is documentation-only and cross-repository, change `bytegeist-docs`. If it describes infrastructure operation, change `infra-configs`. If it is learning material, change `cka-lab`.
